code-smells

A reference catalogue of the 24 code smells from Refactoring, 2nd edition — and a review command that applies it.

What it does

  • Lists every smell from Martin Fowler's Refactoring (2nd ed.), Chapter 3, in the book's order.
  • For each one: the symptom you can point at, and the refactorings that treat it.
  • Reviews code against the catalogue, reporting only smells with a concrete location behind them.
  • Activates on its own when you ask about code quality, or you can run /code-smells directly.

Install

curl -fsSL https://raw.githubusercontent.com/yakovkhalinsky/ai-things/main/install.sh | sh -s -- code-smells

Installs the skill and the /code-smells command into ~/.claude, so they work from any project. Restart Claude Code afterwards.

For a project-local install instead, from a checkout: ./scripts/install.sh copies the same files into the project's .claude/.

Usage

/code-smells                  # review the current changes
/code-smells src/             # review a path
/code-smells feature envy     # look up one smell

Or just ask, for example: “Review this function for code smells.”

Good to know

This is not a linter and not a bug detector. Smells are judgement calls — nothing is broken and the tests may well pass. A small, stable, rarely-touched function with a long parameter list is often fine.

  • The symptom text in the skill is a paraphrase for quick reference, not the book's wording.
  • The Bloaters / Couplers / Dispensables groupings on many websites come from refactoring.guru and the first edition — not from the second.
